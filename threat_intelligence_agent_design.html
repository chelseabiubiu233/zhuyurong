分类互斥原则

每条情报仅归属一个类型。大模型输出 content_type + classification_confidence（置信度 0.0~1.0）。若置信度 < 0.6，标记为待人工复核。

【出于信息安全需要，具体关键词内容不展示】
【任务】 分析输入情报，判断其属于以下四类中的哪一类： 1. 公开漏洞：含CVE编号、安全公告、补丁、PoC、武器化利用 2. 数据泄露：用户数据/车主信息/内部代码/设计图纸泄露 3. 政府监管：工信部通报、网信办处罚、召回、合规检查 4. 舆情情报：社交媒体讨论、车主投诉、车机故障、破解刷机 输出字段： content_type: "vulnerability" | "data_leak" | "regulatory" | "public_opinion" classification_confidence: 0.0~1.0 注意： - 商业/财经/政策新闻顺带提及某新能源车企，未涉及安全问题 → 回退到 irrelevant - 带CVE编号的漏洞通告即使未命中核心资产 → 必须判为 vulnerability - 车机非白名单应用安装、刷机、ADB、root → 属攻击面，判 vulnerability 或 public_opinion

🔴 漏洞类额外处理：CVE提取 + CVSS查询

1. CVE提取：从大模型结果中提取 CVE 编号，合并 normalize 阶段兜底提取的 preliminary_cves
2. NVD反查：精准查询 NVD API 2.0（cveId参数），获取 CVSS v3.1/v3.0/v2.0 评分、严重等级、向量字符串、受影响CPE
3. CVSS融合：仅向上融合，不压低大模型评分。若 NVD CVSS 高于大模型风险分，向上拉 40% 差距
4. 有CVE加分：来源可信度保底 ≥ 75 分
